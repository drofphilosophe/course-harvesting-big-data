Separating columns - Data Types

By default separate creates text (<chr>) columns

  • We think of years as numeric

Let’s do the latter

Combining data

Combining Data from Multiple Data Frames

Think about two data frames that may contain similar information

  • Separate files for different measurements (e.g., CRU)
  • Separate files for different time periods
  • Separate files for different places

Tidyverse methods for combining data

The tidyverse has several methods of combining data frames

  • bind_rows() stacks rows of data frames
  • bind_cols() stacks columns of data frames
  • Joins use more complicated logic to match rows between datasets
    • Covered next week

Stacking Rows

bind_rows() stacks rows of multiple data frames

  • Each data frame is added to the bottom of the previous data frame
  • Useful when you have multiple data frames with the same layout
    • Identical column names
    • Identical data types
  • e.g.,
    • One data frame for each year of data
    • Otherwise identical

Stacking Rows

bind_rows()

  • Returns a single data frame, aligning columns by name
  • Fills in with NA when a column doesn’t exist

Watch out for inconsistent data types!

Each column needs a single data type. R will attempt to coerce values of each column to a single data type, but won’t convert numbers to text or vice versa. This can lead to unexpected NA values if you try to stack a column that switches between text and numeric data!

Two ways to use bind_rows()

Just stack data frames

bind_rows(data_2000,data_2001)

Stack rows from each data fame

But otherwise no way to tell them apart

Stack with identifier column

bind_rows(
  list(
    "2000" = data_2000, 
    "2001" = data_2001
  ),
  .id="Year"
)

Adds a Year column with the corresponding name from the list()

Stacking Columns

bind_cols() stacks columns of multiple data frames

  • Each data frame is added to the right of the previous data frame
  • Useful when you have multiple data frames of information for the same observations
    • Observations align perfectly across each data frame
    • Column names do not overlap
  • e.g., a wide table was split up into multiple files

Stacking Columns

In general you won’t use bind_rows()

  • Few cases where you need to combine columns across data frames by matching rows
  • Only useful when you have full knowledge of the provenance of each data frame, e.g.,
    • You intentionally split off columns from a data frame
    • Want to combine back later
  • No checks for whether observations are correctly aligned
  • Usually use Joins to match observations across dataframes (next week)

Reshaping Data

Reshaping Data Overview

What does it mean to reshape (pivot) data?

  • Take information organized by columns and reorganize in rows or vice-versa
  • Will change the shape of your data frame

pivot_longer()

  • New data are longer and narrower
  • More rows, fewer columns
  • Column information translated into rows

Reshaping Data Overview

What does it mean to reshape (pivot) data?

pivot_wider()

  • New data are wider and narrower
  • More columns, fewer rows
  • Row information is translated into columns

Reshaping Data - The Old Way

  • The pivot functions are relatively new
  • The tidyverse previously used gather and spread
  • They have the superseded lifecycle tag
  • No new features will be added, but won’t be removed soon
  • Harder to use, Fewer features
  • Avoid using them

Pivoting Wider

Using pivot_wider()

When you use pivot_wider() you should ask yourself three questions:

  1. Which column(s) will uniquely identify observation in my new data frame? id_cols
  2. Which column(s) contain information that will be used to construct new column names? names_from
  3. Which column(s) contain values that will populate those new columns? values_from

Each answer tells you what to use for each of the required arguments!

Example pivot_wider()

I would like to create a new version of the CRU data frame

  • One row for each Country-Year
  • Columns for the temperature in each month

How can I do this?

Example pivot_wider()

  • One row for each Country-Year
  • Columns for the temperature in each month
  1. Which column(s) will uniquely identify observation in my new data frame? id_cols
  2. Which column(s) contain information that will be used to construct new column names? names_from
  3. Which column(s) contain values that will populate those new columns? values_from

Example pivot_wider()

  • id_cols = c(Year,Country)
  • names_from = Period
  • values_from = Value

Remove extra columns before pivoting

When pivot_wider() rearranges your data frame it needs to know what to do with information in each column. This is ambiguous for any column that doesn’t show up in one of the three arguments. You should remove columns that aren’t needed with select() before pivoting.

Implement pivot_wider()

Reshape the CRU data to make month columns

  • Remember to remove unneeded columns
  • id_cols = c(Year,Country)
  • names_from = Month
  • values_from = Value

Example pivot_wider()

Code 
cru_tmp |>
  # Keep only columns needed for the pivot
  select(Year,Country,Month,Value) |>
  # Pivot to wider and shorter
  pivot_wider(
    # Columns that uniquely identify observations
    id_cols=c(Country,Year),
    # Column used to create names
    names_from=Month,
    # Column used to fill values
    values_from=Value
  ) -> cru_tmp_wide

Adding a manual legend

The visualization doesn’t contain a legend

  • R only creates a legend when you provide a color aesthetic
  • Here color is a layer property
  • To create a legend, you need to use aesthetics
  • What goes in the aesthetic? Data
  • What is the data that corresponds to the blue line? “January”

Adding a manual legend

You can add a manual legend by

  • Adding the color aesthetic to each layer
  • Setting the color aesthetic value to the label text you want in the legend
  • Using a scale color function to set the specific colors

Adding a manual legend - Example

Code 
# Filter to one country
cru_tmp_wide |>
  filter(Country == "Spain") -> cru_spain

ggplot(cru_spain,aes(x=Year)) +
  # Add the legend text as the color aesthetic
  geom_line(aes(y=JAN,color="January"),linewidth=1) +
  geom_line(aes(y=JUL,color="July"),linewidth=1) +
  theme_bw() +
  labs(
    x="Year",
    y="Average Temperature (C)",
    title="Seasonal Temperature by Year",
    subtitle="Spain",
    color="Month"
  ) +
  # Discrete Viridis Scale
  scale_color_viridis_d() +
  theme(legend.position = "bottom")

Pivoting Longer

Using pivot_longer

pivot_longer will make your data longer and narrower

  • Converts information stored in columns to information stored in rows
  • Effectively the reverse of pivot_wider

pivot_longer Questions

Whenever you use pivot_longer ask yourself the following questions

  1. Which column(s) do I want to transform (pivot)? cols
  2. In what new column(s) should I put the names of these columns? names_to
  3. In what new column(s) should I put the values from these columns? values_to

Challenge - pivot_longer

Use pivot_longer on the wide dataframe we created earlier to undo the previous pivot_wider

Specifying columns in pivot_longer

The cols argument may consist of many columns. In this example it’s all 12 month names. You can use the tidy-select syntax to save yourself typing.

You want to pivot everything except Year and Country so you could use

cols=-c(Year,Country)

Alternatively, the month names are 3 capital letters and you can match each with a Regular Expression and the matches tidy-select function

cols=matches("^[A-Z]{3}$")

  2. Use answers to construct the arguments
