Modern Data File Formats

CSV has been a de facto standard for data

The Bottleneck:

  • Modern datasets like high-resolution climate rasters or satellite indices overwhelm plain text formats like CSV
    • e.g., The FAO data is nearly 400 MB in CSV format
  • Data stored in purely text format
    • Requires software “guess” properties of the data
    • Numeric data needs to be translated from text
    • Repeated text values written out in full, each time
  • CSV files are
    • Slow to read
    • Large
    • Require guesses or manual intervention to read correctly

Modern Big Data Storage

The Next Generation:

Define a data file format for modern big data

  • Portable: Works across data processing systems
  • Fast: Information you need loads quickly
  • Compact: Data stored efficiently for small files
  • Consistent: All software interprets the data identically without guessing

The Parquet Format

Parquet (PAR-kay) is a modern data file format for storing tidy data frames

  • Created in 2013
  • Specification is free and open source
  • Managed by the Apache Foundation
  • Implemented in most data analysis software

Parquet Advantages: Column-orientation

Column-oriented storage

  • In CSV files data are oriented in rows
    • You must read all of one row before moving on to the next
    • Inefficient if you only want data from specific columns
  • Parquet files use a column format
    • Only need to read data for the columns you request

Parquet Advantages: Automatic Compression

Automatic Compression

  • A CSV must write out every value in every cell as text
  • Parquet automatically compresses information
    • Column-oriented files are more compressible in general
    • Dictionary compression of frequent values
    • Run-length encoding for repeated values
    • Delta-encoding efficiently packs sequential numbers/timestamps

Parquet Advantages: Strict Schema

Strict Schema

  • A CSV file doesn’t contain any information about data types
  • Parquet files explicitly define data types of each column
    • Integer, Floating point, Character, Boolean, Date, and Timestamp data types
  • Parquet uses explicit formats for each data type (e.g., IEEE-754 floating point)
  • Any data processing package interprets each value the exact same way
  • Explicit support for missing (NA) values

Parquet Disadvantages

  • Binary files aren’t human-readable
  • Column-oriented format makes “appending” data slow
    • Poorly suited for cases where you frequently update data
  • Performance gains only materialize on larger files
    • 1000s of observations
    • 10s or 100s of columns

Parquet in this Class

In this class I will provide Parquet versions of most data files

  • Data files contain many, repeated text values
  • Very large CSV files
  • Parquet much smaller, so they load quickly
  • Strict schema, so everyone gets the same data

On-the-fly Calculations in Visualizations

A tweak to the labels

  • The values on my vertical axis are in scientific notation
    • R defaults to using it when values are larger than 1000
    • Or smaller than 0.1
  • Sometimes difficult to read
  • Options for improving:
    • Force R to format numbers in fixed-comma format (8,000,000)
    • Rescale the axis so numbers are smaller (million mt vs mt)

Rescale values on-the-fly

The cleanest choice is to rescale the vertical axis

  • Show “million mt” instead of “mt”
  • Requires dividing Value by 1,000,000
  • In ggplot you can do this math “on-the-fly” in a visualization
...
  aes(x=Year,y=Value/1000000)
...
  • Any mathmatical operation is supported
  • Summary functions (e.g., mean()) will compute the value over all data in that layer

My visualization

Code 
ggplot(
  data=fao_filtered,
  mapping=aes(x=Year,y=Value/1000000)
) +
  geom_line(color="black") +
  geom_smooth(color="blue",se=FALSE) +
  labs(
    title="Wine Production in France",
    x="Year",
    y="Production (million mt)",
    caption="Source: United Nations FAOSTAT"
  )

Customizing an Axis

Visualization Scales

  • R automatically adjusts the scale of each axis to fit the data
    • Minimum value slightly smaller than smallest value
    • Maximum value slightly larger than largest value
  • Can exaggerate how much values change over time
  • In the previous visualization, you may want to extend the axis to zero

Adjusting Visualization Axes

  • Adjust axis properties using scale functions
  • Take the form: scale_<axis>_<type>()
  • <axis> is x or y
  • <type> is the axis type
    • Determines how the axis will be drawn
    • Depends on the type of data you’re plotting

Adjusting Visualization Axes

Axis Scale Resources

The Help feature in RStudio has excellent documentation, start by typing “scale_” in the search box.

There is also an excellent resource for using scales at

Adjusting a Continuous Axis

The vertical axis in our visualization is continuous

  • Customize using scale_y_continuous()
  • Read the help for this function
  • There will be some things that make sense and some thing less so
  • Important options (look closely at them)
    • limits
    • breaks
    • minor_breaks

Adjusting a Continuous Axis

Arguments for scale_y_continuous()

  • limits
    • A 2-element vector with the starting and ending value of the axis
  • breaks
    • A vector with the major (labeled) break values on the axis
  • minor_breaks
    • A vector with the minor (unlabeled) break values on the axis

  )

Storing Visualizations

Storing visualizations

You can store a ggplot visualization using an assignment operator (e.g., ->)

  • Stores everything needed to create the visualization in a named variable
  • Does not render the visualization
  • You can render/display it later with print()
  • Why would you do this?
    • Create many visualizations then print/save them all at once
    • You can modify a stored visualization by adding more layers or attributes

Storing a Visualization

This stores my visualization, but does not show it!

ggplot(
  data=fao_filtered,
  mapping=aes(x=Year,y=Value/1000000)
) +

    title="Wine Production in France",

Saving Visualizations

Saving Visualizations

Visualizations are most useful if you can share them

  • R Studio’s Plots viewer allows saving visualizations
    • Several steps
    • Not Automated
    • Required every time you update the visualization
  • You can add code to save a visualization with ggsave()
    • Visualization will be saved each time you run your R code
    • Apply specific options to the saved file (file format, size)

Using ggsave

To save a visualization use

ggsave(<output_path>)

  • R determines the output format using the file extension
    • e.g., .png, .jpg, .pdf
  • Some important optional arguments are:
    • plot: A variable containing the plot to save
      • Otherwise, the default is the last plot generated
    • width: Width of the saved image in inches
    • height: Height of the saved image in inches

Example Saving a Visualization

# Set a path to a directory where you can save files
homedir_path = "/home/username/Documents/AREC280"

ggsave(
  file.path(homedir_path,"wine_production.png"),
  plot=production_viz,
  width=16,
  height=9
)

Choosing a Visualization File Format

You have several choices for file formats, which have advantages and disadvantages

  • PDF files best for publication quality graphics
    • Are vector images, they scale up flawlessly to very large image sizes
    • Complicated visualizations make large output file that load slowly
  • PNG files best for general use
    • Are raster images, they will get blocky as you scale them up
    • Files will be a fixed size no matter how complicated the visualization
  • JPG files best for websites/text messages
    • Also raster images but use Lossy Compression
    • Files tend to be very small, nearly anyone can view them
    • Underlying compression algorithm can lose details
  • There are other, more niche formats available too
