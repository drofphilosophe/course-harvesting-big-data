# **AREC 280 Course Repository & Quarto Presentation Style Guide**

This document provides setup instructions, project architecture standards, and technical specifications for managing and authoring slide decks and course materials within this repository.

## **1\. Initial Repository Setup**

Follow these steps when setting up the repository on a new machine.

### **Prerequisites**

* **Quarto CLI** (v1.3 or higher)  
* **Git**  
* **R** (with here and dotenv packages installed) 

In the case that the course will include coding content in Python

* **Python 3.10+** (with python-dotenv and pandas installed)

### **Setup Procedure**

1. **Clone the Repository:**

```
git clone https\://github.com/your-username/your-repo-name.git  
cd your-repo-name  
```

2. **Configure Local Environment Variables (.env):**  
  * Copy the template configuration file:
    ```
    cp .env.example .env  
    ```
  * Open `.env` and update `GDRIVE_PATH` to point to the absolute path of your Google Drive course data folder on this computer:  
     * **macOS Example:** 
     
     `GDRIVE_PATH="/Users/username/Google Drive/Shared Drives/AREC280_<Year>_<Semester>"`
     
     * **Windows Example:** 
     
     `GDRIVE_PATH="g:\Shared Drives\AREC280_<Year>_<Semester>"`

3. **Verify Git Exclusions:**  
Ensure your local `.env` and rendered `_site/` directory are excluded from Git tracking in 
`.gitignore`. This file is part of the repository and should be synnced on the initial clone:  
  * `.env`
  * `_site/`
  * `.Rproj.user/`
  * `.quarto/`
  * `.Rhistory`

## **2\. Directory Structure & Organization**

The repository uses a Quarto Website (type: website) project structure. Source files are strictly separated from rendered web files and external data binaries.
```
my-course-repo/  
├── _quarto.yml            # Master configuration (navigation, global SCSS, site settings)  
├── index.qmd               # Course homepage / Syllabus landing page  
├── .env.example            # Environment variable template committed to Git  
├── .env                    # Machine-specific paths (GIT-IGNORED)  
├── .gitignore              # Git exclusion rules  
│  
├── assets/                 # Lightweight static visual assets committed to Git  
│   ├── images/             # Diagrams, icons, diagrams (compressed PNG/SVG/WebP)  
│   └── logos/  
│  
├── _extensions/           # Presentation styling extensions  
│   └── custom-theme/       # SCSS styles and RevealJS theme modifications  
│  
├── modules/                # Course content divided into semantic topic folders  
│   ├── intro/  
│   │   ├── 01-welcome.qmd  
│   │   └── 02-setup.qmd  
│   ├── python-basics/  
│   │   └── 01-variables.qmd  
│   └── statistics/  
│       └── 01-regression.qmd  
│  
└── _site/                 # Output folder generated by Quarto (published to GitHub Pages)
```

### **Naming Conventions**

* **Module Directories:** Use lower-case, hyphenated semantic names without numeric prefixes (e.g., `modules/python-basics/`, not `modules/01-python/`). This allows reordering modules without refactoring directory names.  
* **Slide Files (`.qmd`):** Use two-digit ordered prefixes within module subdirectories (e.g., 01-welcome.qmd, 02-setup.qmd).  
* **Images:** Lower-case, descriptive, hyphenated (e.g., `assets/images/data-pipeline-diagram.png`).

## **3\. Master Site Configuration (\_quarto.yml)**

The `_quarto.yml` file controls site structure, global theme settings, and module ordering.  
```{yaml}
project:  
  type: website  
  output-dir: _site

execution:  
  execute-dir: project   # Forces code execution to run relative to project root

website:  
  title: "Course Title"  
  sidebar:  
    contents:  
      - text: "Course Overview"  
        href: index.qmd  
      - section: "Module 1: Introduction"  
        contents:  
          - modules/intro/01-welcome.qmd  
          - modules/intro/02-setup.qmd  
      - section: "Module 2: Python Fundamentals"  
        contents:  
          \- modules/python-basics/01-variables.qmd  
      - section: "Module 3: Applied Statistics"  
        contents:  
          - modules/statistics/01-regression.qmd

format:  
  revealjs:  
    theme: [_extensions/custom-theme/custom.scss]  
    slide-number: true  
    controls: true  
    chalkboard: true  
    preview-links: auto  
    history: true  
```
  
* **Module Reordering:** To change the sequence of topics or move slide decks between modules, reorder the entries in `_quarto.yml`. Do not rename physical folders on disk.

## **4\. Slide Deck Standards & Authoring Guidelines**

### **Quarto Header (YAML Frontmatter)**

Every `.qmd` slide deck should keep header configurations minimal, relying on global settings in `_quarto.yml`:  
```{yaml}
---  
title: "Deck Title Here"  
subtitle: "Module Name or Subtitle"  
author: "Instructor Name"  
format: revealjs  
---  
```

**Rules:**

* Do **not** include embed-resources: true or standalone: true. Shared assets compile into `_site/site_libs/`  
* Do **not** override theme files locally unless specific slide customization is required.

### **Accessing External Google Drive Data in Code Chunks**

Do not hardcode machine paths or rely on absolute local paths. Use the designated project-root utility pattern for both languages.

#### **R Code Pattern**

```
#| echo: false  
# Load local .env from project root regardless of folder depth  
here::i_am(".env")
env_path <- here::here(".env")
if (file.exists(env_path)) {
  readRenviron(env_path)
} else {
  stop(paste("Unable to locate .env file at ", env_path))
}

# Extract Google Drive path  
gdrive_path <- Sys.getenv("GDRIVE_PATH")

# Construct file path dynamically  
course_path <- file.path(gdrive_path, "Shared Drives", "AREC280_<Year>_<Semester>")
```

Then reference `data_path` in later code. Provide an unexecuted setup chunk for students:
```
#| eval: false
# Set the path to the Google Shared Drive for this course
course_path <- "g:/Shared Drives/AREC280_<year>_<semester>"
``` 


#### **Python Code Pattern**

```
#| echo: true  
import os  
from pathlib import Path  
from dotenv import load_dotenv, find_dotenv  
import pandas as pd

# Find .env automatically by traversing up directories  
load_dotenv(find_dotenv())

# Extract path and construct OS-agnostic path object  
gdrive_path = Path(os.getenv("GDRIVE_PATH"))  
course_path = gdrive_path / "Shared Drives", "AREC280_<Year>_<Semester>"
```

The provide an unexecuted setup chunk for students:
```
#| eval: false
from pathlib import Path
# Set the path to the Google Shared Drive for this course
course_path <- Path("g:/Shared Drives/AREC280_<year>_<semester>")
```

### **Static Image Inclusion**

Store all reusable or shared images inside `assets/images/`. Reference them in markdown using relative paths from the project root, e.g.,:
```
![Data Flow Diagram](/assets/images/data-pipeline-diagram.png){width=80%}
```

## **5\. Build, Render, and Deployment Workflow**

### **1\. Rendering Decks**

* **Render a Single Presentation (Fast preview during editing):**
```{bash}
quarto render modules/intro/01-welcome.qmd  
```

* **Render the Entire Site (Batch update all decks):**
```{bash}
quarto render
```

### **2\. Publishing to GitHub Pages**

Deploy the compiled site directly from your local environment to the gh-pages branch using Quarto's CLI:
```{bash}  
quarto publish gh-pages  
```

This command automatically:

1. Renders all .qmd files into `_site/`.  
2. Creates or updates the gh-pages branch in your remote Git repository.  
3. Deploys the static site to <https://your-username.github.io/your-repo-name/>.

## **6\. Maintenance & Asset Management Rules**

| Item | Storage Location | Rules & Restrictions   |
| :---- | :---- | :---- |
| **Source Slides (.qmd)** | `modules/\<module-name>/` | Tracked in Git. Text only. |
| **Custom Styling (.scss)** | `_extensions/custom-theme/` | Tracked in Git. Edits apply globally across all decks. |
| **Small Visuals/Logos** | `assets/images/` | Tracked in Git. Compress images under 500 KB before committing. |
| **Large Datasets (\>1 MB)** | Google Drive (`GDRIVE_PATH`) | **Never** commit to Git. Reference dynamically via .env. |
| **Rendered Web Files** | `_site/` | Automatically generated. Excluded from main Git branch (.gitignore). |
